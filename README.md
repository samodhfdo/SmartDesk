# SmartDesk

SmartDesk is an IT Service Management (ITSM) platform for reporting, assigning and resolving internal IT support incidents.

## Technology
- Java 21
- Spring Boot 3.5
- Spring Web, Spring Data JPA, Bean Validation
- PostgreSQL 16
- Flyway database migrations
- Maven

## Initial scope
This starter implements the first ticket-management API slice:
- Create a ticket
- List tickets
- Retrieve a ticket by ID
- Update ticket status

Authentication, role-based access, assignment workflows, comments, audit history, frontend, tests and CI/CD are planned milestones.

## Prerequisites
- JDK 21
- Maven 3.9+ (or use the Maven wrapper generated by your IDE)
- Docker Desktop

## Run locally
1. Start PostgreSQL:
   ```bash
   docker compose up -d
   ```
2. Run the API:
   ```bash
   mvn spring-boot:run
   ```
3. API base URL: `http://localhost:8080/api`

Flyway creates the initial database schema on startup.

## Initial API endpoints
| Method | Endpoint | Purpose |
|---|---|---|
| POST | `/api/tickets` | Create a ticket |
| GET | `/api/tickets` | List tickets |
| GET | `/api/tickets/{id}` | Get a ticket |
| PATCH | `/api/tickets/{id}/status` | Update status |

## Example create request
```json
{
  "title": "Laptop cannot connect to Wi-Fi",
  "description": "The device detects the network but fails to connect.",
  "priority": "HIGH",
  "categoryId": 1,
  "reporterId": 1
}
```

The initial migration inserts a sample category and sample employee. This is development seed data only; authentication and production-grade user provisioning will be added later.

## Engineering principles
- Keep controllers thin; business rules belong in services.
- Use DTOs at the API boundary rather than exposing entities.
- Use database migrations instead of relying on Hibernate schema generation.
- Add tests for business rules and API behaviour as features are introduced.
- Never commit real secrets or production credentials.
